# as30 — ISP-B (AS30)

Proveedor de tránsito de AS20 y AS60, miembro del IXP. Ilustra la **política con large
communities**, **RPKI en todas las entradas**, **vecinos dinámicos** (`listen range`),
**tabla parcial** (`default-originate`), **MED** y **sesiones IPv4 que transportan IPv4 e
IPv6**.

## Vecinos

| Vecino | AS | Familia | Notas |
|---|---|---|---|
| `10.0.2.1` | 20 | IPv4+IPv6 | EmpresaA, una sesión IPv4 con las dos familias |
| `10.0.4.2` | 40 | IPv4+IPv6 | tránsito, una sesión IPv4 con las dos familias |
| `10.0.7.0/30` | — | IPv4 | vecinos dinámicos (AS60 aparece como `*`) |
| `192.168.0.1` | 100 | IPv4+IPv6 | route server, `ttl-security hops 1`, `local-role rs-client` |

## Large communities de AS30 (`ASN:funcion:parametro`)

| Comunidad | Significado |
|---|---|
| `30:1:100` | aprendida de un cliente → `local-preference 200` |
| `30:1:200` | aprendida en el IXP → `local-preference 150` |
| `30:1:300` | aprendida de un proveedor → `local-preference 100` |

## Vecinos dinámicos y tabla parcial

```text
neighbor CLIENTES-DIN peer-group
neighbor CLIENTES-DIN remote-as external
bgp listen range 10.0.7.0/30 peer-group CLIENTES-DIN
bgp listen limit 5
...
neighbor CLIENTES-DIN default-originate
neighbor CLIENTES-DIN prefix-list sololadefault out
```

No se declara a AS60: se acepta a cualquiera que conecte desde `10.0.7.0/30`. Se le envía
**solo la ruta por defecto** (tabla parcial), lo que contrasta con ISP-A que le manda la
tabla completa.

## MED

Hacia AS20 usa `route-map a-as20` con `set metric 30`, para influir en la elección de
camino del cliente multihomed (MED).

## Para inspeccionar

```bash
./lab.sh vty as30 "show bgp ipv4 unicast summary"        # vecino dinamico marcado con *
./lab.sh vty as30 "show bgp ipv4 unicast large-community 30:1:100"
./lab.sh vty as30 "show bgp ipv4 unicast 20.0.0.0/21"
```

Ver la configuración: `configs/as30/frr.conf`.
