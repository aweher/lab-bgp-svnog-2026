# as40 — "Internet" (AS40)

Tránsito de AS10, AS30, AS41 y AS50. Es la **configuración mínima** de eBGP (el slide
"Configuración básica de eBGP"): no tiene route-maps ni prefix-lists. También es el
ejemplo de **multipath** y de **BGP sin numerar con next-hop IPv6 para IPv4 (RFC 8950)**.

## Vecinos

| Vecino | AS | Familia | Notas |
|---|---|---|---|
| `2001:db8:0:3::1` | 10 | IPv4+IPv6 | ISP-A, una sesión IPv6 con las dos familias |
| `10.0.4.1` | 30 | IPv4+IPv6 | ISP-B, una sesión IPv4 con las dos familias |
| `10.0.5.1` | 50 | IPv4+IPv6 | contenido |
| `eth3` | 41 | IPv4+IPv6 | enlace sin direcciones (solo link-local) |

## Puntos clave

- `no bgp ebgp-requires-policy`: desactiva la RFC 8212. Sin esta línea, las sesiones eBGP
  sin política no aceptan ni anuncian nada (es la **falla 4** en otros nodos).
- `maximum-paths 2` + `bgp bestpath as-path multipath-relax`: reparte tráfico entre
  caminos con AS-PATH distinto pero del mismo largo (los dos caminos hacia AS20).
- Enlace `eth3` sin numerar: `neighbor eth3 interface remote-as 41`, con `ipv6 nd
  ra-interval` para generar las link-local. Las rutas IPv4 viajan con next-hop IPv6
  gracias a la capacidad de la RFC 8950.

## Para inspeccionar

```bash
./lab.sh vty as40 "show bgp summary"
./lab.sh vty as40 "show bgp ipv4 unicast"
./lab.sh vty as40 "show ip route 20.0.0.0/21"        # dos next-hops (multipath-relax)
./lab.sh vty as40 "show bgp ipv4 unicast 41.0.0.0/16" # next-hop IPv6 (RFC 8950)
```

Ver la configuración: `configs/as40/frr.conf`.
