# as10 — ISP-A (AS10)

Proveedor de tránsito de AS20, AS60 y AS66. Ilustra la **política de un ISP con
comunidades clásicas**, la **local-preference por tipo de vecino**, la aceptación de
**RTBH**, `maximum-prefix`, **BFD**, **dampening** y **BGP Roles**.

A propósito **no valida RPKI y no filtra a AS66**: así se puede ver hasta dónde llega un
secuestro de prefijos.

## Vecinos

| Vecino | AS | Familia | Notas |
|---|---|---|---|
| `10.0.1.1` | 20 | IPv4 | EmpresaA, `password`, `bfd`, `disable-connected-check`, `local-role provider strict-mode` |
| `2001:db8:0:1::1` | 20 | IPv6 | "doble peer" |
| `2001:db8:0:3::2` | 40 | IPv4+IPv6 | una sesión IPv6 con las dos familias (tránsito) |
| `10.0.6.1` | 60 | IPv4 | cliente, `local-role provider` |
| `10.0.8.1` | 66 | IPv4 | cliente, **sin filtro de entrada** (mala práctica a propósito) |

## Comunidades clásicas de AS10

| Comunidad | Significado |
|---|---|
| `10:100` | aprendida de un cliente → `local-preference 200` |
| `10:300` | aprendida de un proveedor → `local-preference 100` |
| `65535:666` | blackhole (RFC 7999): solo de clientes y para sus `/32` |

## RTBH

`route-map de-as20 permit 10` matchea la comunidad `blackhole` + el prefix-list de `/32`
del cliente, y setea `next-hop 192.0.2.1` (ruta estática a Null0). Por eso existe
`ip route 192.0.2.1/32 Null0` y `disable-connected-check` en el vecino.

## Dampening

`bgp dampening` con los valores por defecto de FRR. Cuatro oscilaciones de AS66 alcanzan
para suprimirlo más de media hora (escenario `flaps`).

## Para inspeccionar

```bash
./lab.sh vty as10 "show bgp ipv4 unicast community 10:100"
./lab.sh vty as10 "show bgp ipv4 unicast 20.0.0.0/22"    # no-advertise de AS20
./lab.sh vty as10 "show bgp ipv4 unicast dampening dampened-paths"
```

Ver la configuración: `configs/as10/frr.conf`.
